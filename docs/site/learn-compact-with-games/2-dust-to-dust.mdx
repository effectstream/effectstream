## Technical challenges

### Time-based quests

Quests open and close on real elapsed time, not just on player action. We
walk through how we anchor "now" in a way both the game and the contract
agree on, and how we keep the UI honest when the player's clock disagrees
with the chain.

### Tradeable characters via the offer file system

Trades happen between two players who don't trust each other. We use an
offer file flow so each side can publish, inspect, and accept proposals
without ever putting an asset at risk mid-trade.

### Witness functions

Witness functions let the contract consume private inputs the player
already has, without leaking them. This section is the longest one in the
post - it's the first time in the series we use the primitive that defines
much of what comes next.

### Building on Phaser

Phaser handles rendering, input, and the tilemap. We cover how we wire its
scene system into the contract calls without making either side care too
much about the other.
