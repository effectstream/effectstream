## Technical challenges

### Arbitrum finality

The same finality argument as BlockKart, but applied to a different shape
of game. A puzzle that takes fifty inputs to solve is fifty chances to
feel sluggish if settlement is slow.

### Many simple actions

Each move in Safe Solver is tiny. We talk through how we keep these moves
cheap individually, how we batch where it makes sense, and how the
contract validates a sequence without making the client wait between
clicks.

Safe Solver is a click-heavy puzzle. Like BlockKart, all of the per-click game state runs off-chain on Arbitrum, and Midnight's Compact contract is a write-once notarization layer. The contract below is byte-for-byte identical to BlockKart's - same architectural pattern emerging from a different game's constraints.

### Same anchor pattern, different reason

BlockKart needed off-chain speed for racing. Safe Solver needs off-chain speed for *volume* - dozens of small actions per round would be prohibitively expensive to verify on Midnight directly. Pushing the per-click state machine onto Arbitrum and using Compact only as an anchor is the same design choice for a different reason. When your contract starts looking like this short, ask whether you actually need the rest of Compact's expressiveness or whether the chain is just your notary.
