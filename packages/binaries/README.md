# packages/binaries

> [!WARNING]
> **These packages are for development only. Do not use them in production.**
> They download prebuilt blockchain and observability binaries and execute them
> on the developer's machine to stand up a local multi-chain environment. They
> are not hardened, not sandboxed, and their configuration defaults (open RPC
> ports, dev credentials, regtest/sandbox networks) are deliberately insecure
> conveniences for local development.

Each package here is an NPM wrapper around a prebuilt binary (Bitcoin Core,
Grafana Loki, the Agave test validator, …). The wrapper downloads the right
asset for the current platform via
[`bin-wrapper`](https://github.com/XhmikosR/bin-wrapper), then runs it. The
orchestrator (`packages/build-tools/orchestrator`) composes them into a local
environment.

## Integrity: how downloads are verified

`bin-wrapper` has no checksum support and discards the archive after
extracting, so verified wrappers hash the **extracted binary** and refuse to
run anything that is not in a pinned set of SHA-256 digests. The check itself
lives in [`binary-checksum/`](./binary-checksum) and the per-package digest
tables in each package's `checksums.js`.

Digest tables record **provenance** per entry:

- `upstream-verified` — the archive the digest came from was matched against a
  checksum the vendor publishes, so the digest traces back to the vendor.
- `self-recorded` — hashed from a download with no upstream manifest to check
  against. Pins the artifact against *later* mutation, but does not attest it
  was correct to begin with.

Current coverage:

| package | verified | provenance |
|---|---|---|
| `bitcoin-core` | yes | upstream-verified |
| `grafana-loki` | yes | upstream-verified |
| `grafana-alloy` | yes | upstream-verified |
| `solana-node` | yes | self-recorded |
| `ord` | no | upstream publishes no `SHA256SUMS` |
| `celestia`, `midnight-*` | no | downloads come from `effectstream/binaries` re-hosting, so a digest would pin the copy, not the original release |
| `avail-*`, `near-sandbox`, `midnight-indexer` | no | not yet wired up |

Every verified wrapper accepts a `<PACKAGE>_SKIP_CHECKSUM=1` env var (e.g.
`BITCOIN_CORE_SKIP_CHECKSUM=1`) to deliberately run a local build. Only the
exact value `1` bypasses the check.

## Maintaining a verified wrapper (version bumps)

The digest tables are generated by
[`scripts/generate-binary-checksums.ts`](../../scripts/generate-binary-checksums.ts).
The version and download URLs are pinned in **two places** and both must move
together:

1. Bump `version` (and any URL it feeds) in the wrapper's `index.js`.
2. Update the matching entry in the `SPECS` array of
   `scripts/generate-binary-checksums.ts` — the script does **not** read the
   wrapper's source, so a bump that skips this step regenerates digests for the
   *old* version and the wrapper will fail closed at runtime with a confusing
   mismatch.
3. Regenerate the table:

   ```bash
   bun scripts/generate-binary-checksums.ts <package-dir>   # e.g. bitcoin-core
   ```

4. Update the version mentioned in the package's README "Integrity" section.

`bun scripts/generate-binary-checksums.ts --check` re-downloads everything and
reports drift without writing. Never edit a `checksums.js` by hand — an empty
or hand-edited table defeats the provenance the generator records, and an empty
table makes the wrapper refuse to run at all (fail closed by design).

## Adding verification to a new wrapper

1. Add `"@effectstream/binary-checksum": "workspace:*"` to the package's
   dependencies, and make sure the package has `"type": "module"`.
2. In the wrapper, download and verify **before** anything executes or mutates
   the binary — `bin.run()` resolves the binary *and executes it*, so it must
   come after the check:

   ```js
   import { verifyBinaryChecksum } from '@effectstream/binary-checksum';
   import { CHECKSUMS } from './checksums.js';

   if (!fs.existsSync(bin.path())) await bin.download();
   verifyBinaryChecksum({
     binaryPath: bin.path(),
     checksums: CHECKSUMS,
     packageName: '<package-dir>',
     skipEnvVar: '<PACKAGE>_SKIP_CHECKSUM',
     version,
   });
   await bin.run(['--version']);
   ```

   Watch for anything that rewrites the binary between extraction and
   execution — `bitcoin-core` ad-hoc signs on Apple Silicon, which changes the
   hash, so there verification is a download-time check only and must stay
   above the signing call.
3. Add a `SPECS` entry in `scripts/generate-binary-checksums.ts` with the
   platform assets, the binary's basename inside each archive, and — when the
   vendor publishes one — the `SHA256SUMS` URL, so the digests are
   `upstream-verified` rather than `self-recorded`.
4. Run the generator to produce `checksums.js`, and add an "Integrity" section
   to the package README (copy one of the existing ones).
